# Pixel HQ Dark: fork notes

This repo is a fork of [bnhan2710/pixel-hq](https://github.com/bnhan2710/pixel-hq) with a true dark surface palette.
Upstream's README describes the layout itself. This file covers what is different here and how to keep up with upstream.

## What differs from upstream

| Change | Where |
| --- | --- |
| The updater downloads releases from this fork, not upstream | `mods/company-agents/updater.js` (`REPO_API`, `REPO_RAW`) |
| Six surface shades are Neutral true dark instead of Catppuccin | generated by `scripts/recolor.py` across the `company-*` mods, `layouts/pixel-hq.json` and the background in `themes/pixel-hq.json` |
| Palette presets | `scripts/palettes.json` |
| Local installer with a palette switch | `scripts/install-local.sh` |
| Recolor tests | `tests/test-recolor.test.py` (standalone, not in `run-all.sh`) |

Accent and status colors, the office scene's own colors and the pets are currently unchanged (issues opened for each pending change).

The repo always holds **neutral**. Other palettes exist only in your local install:

```sh
scripts/install-local.sh                   # neutral
scripts/install-local.sh --palette oled    # or tinted, catppuccin
```

The installer backs up the current install to `~/.config/herdr-app-backup-<timestamp>/`, recolors a staged copy,
mirrors it into `~/.config/herdr-app/` and runs `herdr-app check` on every mod. Herdr picks the change up live;
if it does not, quit and reopen it once. OLED repeats `#000000`, so it can be installed but never used as `--from`.

## Setup on a new clone

```sh
git remote add upstream https://github.com/bnhan2710/pixel-hq.git
git config remote.upstream.tagOpt --no-tags   # upstream's tags would collide with this fork's
git config rerere.enabled true                # remember conflict resolutions across merges
```

## Syncing with upstream

```sh
git fetch upstream
git switch -c sync/upstream-$(date +%Y%m%d)
git merge upstream/main
python3 scripts/recolor.py --check --from catppuccin    # new upstream code brings Catppuccin shades
python3 scripts/recolor.py --from catppuccin --to neutral
python3 tests/test-recolor.test.py && bash tests/run-all.sh
scripts/install-local.sh && herdr-app status
```

Commit the recolor separately from the merge, so it is clear what was generated.

**Conflicts.** Most conflicts will be a line upstream changed that the recolor also changed.

- If this fork's only change to the file is the recolor, take upstream's side and regenerate:
  `git checkout --theirs <file> && python3 scripts/recolor.py --from catppuccin --to neutral`.
- `updater.js`: keep upstream's version of everything except the two `REPO_*` lines.
- Leave files you do not use (`stats.*`, `README.vi.md`, the workflows) as they are. Deleting them turns every
  upstream update to them into a modify/delete conflict.
- Keep edits to `README.md` to the banner at the top; put fork notes here.

## Releases

The updater only accepts release tags that match `vX.Y.Z` exactly (`updater.js`, `parseRelease`),
and only offers one newer than the installed version (currently `1.8.7`). This fork has no releases yet, so the
updater stays quiet. Decide on a numbering scheme before tagging the first one: upstream's tags are not fetched,
so reusing upstream's number after a merge does not collide inside this repo.

## Known upstream test failures

These fail on untouched upstream code on macOS, not because of the fork:

- `tests/test-music-player.test.py` test 4 (strict PID check) treats `sleep 10 ffplay mpv` as a player.
- `tests/test-live-e2e.test.sh` expects the live Codex model to be `gpt-6-luna` or `gpt-5.4`.

`run-all.sh` stops at the first failure, so run the suites after the music player test by hand until these are fixed.
